# Let It Snow — внешний API, синхронизация и OBS (v3.1.1)

[English](./EXTERNAL_API.md) | **Русский**

Версия 3.1.1 позволяет другим программам и страницам управлять снегом во время работы:
внезапные снежные взрывы, сильный ветер, заданные символы и дождь из GIF. Кроме того, она умеет
синхронизировать множество окон (в одном или нескольких браузерах) и OBS.

Пошаговая настройка и использование описаны в [руководстве пользователя](./USAGE_RU.md).

Все внешние возможности **по умолчанию выключены** и управляются из всплывающего окна:
**Настройки → API**.

## Команды

Все команды имеют одинаковую JSON-структуру:

```json
{ "command": "burst", "params": { "count": 400 }, "id": "optional-request-id" }
```

Каждое звено (API страницы, фоновый скрипт, relay, оверлей OBS, контент-скрипт) заново проверяет команды.
Неизвестные поля отбрасываются, числа ограничиваются допустимым диапазоном, а строки, цвета и URL
сверяются с белыми списками. Эффекты выполняются на временных слоях поверх основного снега. Одновременно
работает не более 4 слоёв; лишний запрос возвращает `effect_limit_reached`, не удаляя
существующие частицы. `burst` и `glyphs` однократно создают ровно `count` частиц без
повторного спауна и завершаются после падения последней за нижнюю границу.
Их `durationMs` принимается для совместимости, но игнорируется. GIF-слои по-прежнему затухают по таймеру.

| Команда        | Параметры (по умолчанию → диапазон)                                                                                                                                                      |
|----------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `ping`         | —                                                                                                                                                                                        |
| `start`        | `config`: `snowmax` (1–320), `sinkspeed` (0.1–3), `snowminsize`/`snowmaxsize` (2–10), `colors` (≤12 `#hex`), `symbols` (≤16), `glyphMode` (`text`/`emoji`), `rendererMode` (`auto`/`3d`), `windEnabled`, `windDirection`, `windStrength` (0–3), `windGustFrequency` (0.5–10). Недостающие значения берутся из сохранённых настроек. |
| `stop`         | — (останавливает основной снег и все эффекты)                                                                                                                                            |
| `burst`        | `count` 250 → 1–600, `durationMs` 6000, `speed` 1.6 → 0.1–6, `symbols`, `colors`, `entry` `instant`/`top` (по умолчанию `instant`: весь взрыв входит сверху одной плотной волной; `top` — постепенно) |
| `wind`         | `enabled` true, `direction` `left`/`right`/`random`, `strength` 1.6 → 0–3, `gustFrequency` 5 → 0.5–10, `durationMs` 8000 (`0` — до следующей команды `wind`)                               |
| `glyphs`       | **`symbols`** (обязательно, ≤16 символов, ≤16 кодовых точек в каждом), `glyphMode` `text`/`emoji`, `colors`, `count` 60 → 1–300, `durationMs` 10000, `speed` 0.8, `entry` `top`            |
| `gif`          | **`urls`** (или `url`, ≤5): `https://` с фильтрацией имени хоста (без распространённых частных/loopback-адресов и локальных имён, без учётных данных, только порт 443) либо `data:image/(gif\|png\|webp\|apng);base64`. `count` 12 → 1–60, `durationMs` 10000, `speed` 0.8, `entry` `top` |
| `clearEffects` | — (удаляет все временные слои и восстанавливает ветер)                                                                                                                                  |

### Управление, добавленное в 3.1.1

- `burst` принимает **обе** координаты `x` и `y` (конечные числа, CSS-пиксели viewport от левого верхнего угла,
  с ограничением границами экрана). Новые частицы создаются в этой точке с радиальным импульсом;
  `entry` в этом случае игнорируется. `symbols` задаёт символы, `glyphMode: "emoji"` — режим Emoji.
  Взаимные столкновения внутри координатного взрыва отключены, чтобы частицы расходились из общей точки естественно; ветер и взаимодействие с указателем сохраняются.
- `status`: возвращает `{ok, running, paused, main, effects}`. `main` — `null` или
  `{paused, particles, settled, accumulationEnabled}`; в `effects` те же поля и `id` каждого слоя.
- `pause` / `resume`: пауза/продолжение основного снега и всех эффектов, включая новые слои.
  Явная пауза сохраняется при переключении вкладок; продолжение ожидает возвращения на скрытую страницу.
- `update`: `{config: {...}}` меняет **основной слой** без перезапуска и сброса частиц.
  Допустимы `sinkspeed` (0.1–3), `mouseRadius` (0–300), `accumulationEnabled` (boolean),
  `windEnabled`, `windDirection`, `windStrength`, `windGustFrequency` (диапазоны как у `start`).
  Пустое обновление/только неподдерживаемые поля дают `live_config_required`; отсутствие основного снега — `not_running`.
  Активное переопределение `wind` имеет приоритет до завершения или отмены.
  Для изменения внешнего вида/числа частиц используйте `start`. Настройки действуют в сессии, не сохраняются в popup.
- `start.config` также принимает `mouseRadius` и `accumulationEnabled`.
- `clearAccumulation`: осыпает сугробы на **всех слоях**, не удаляя частицы и не останавливая снег.

```json
{"command":"burst","params":{"x":400,"y":250,"count":80,"symbols":["🎉","⭐"],"glyphMode":"emoji"}}
{"command":"update","params":{"config":{"sinkspeed":1.2,"accumulationEnabled":false}}}
{"command":"status"}
```

Накопление включено по умолчанию. Общий анализ DOM проверяет до 2000 элементов
и 80 видимых поверхностей за проход (кэш 750 мс). Emoji размером 4–48 CSS-пикселей
могут лежать рядами с опорой **над** карточками, изображениями и структурными блоками,
если в полосе размещения не обнаружены текст, медиа или элементы управления.
Общий лимит — 32 осевшие частицы на все слои, с промежутками без перекрытий.
Оверлеи не перехватывают клики. **Таймера отлипания нет**. Новая снежинка заменяет
осевшую только при достаточной скорости удара (от 100 CSS-пикселей/с по нормали контакта)
и энергии: `(размерНовой / размерОсевшей)^2 * (скорость^2 + 2 * положительноеУскорение * размерНовой) >= 160^2`.
При слабом ударе снежинка отскакивает/скатывается и может упасть на свободное место рядом,
без переноса или притягивания к координатам слота. Посадка возможна только после физического
достижения высоты опоры. Если первый ряд рядом заполнен, прямой контакт может образовать второй ряд.
Если снежинка с опорой 0,3 секунды не может падать или скатываться, она становится частью
сугроба и в верхних рядах, без изменения позиции. Вся полоса посадки проверяется на информацию
и верхнюю границу экрана. Контакты с сугробом
проверяются по траектории движения (включая боковые удары), до коллизий движущихся частиц.
При сбивании нижней опоры осыпаются и лежащие на ней снежинки.
Проверка покоя использует итоговые координаты после коллизий и допускает микродрожание контакта.
Сбитые частицы проходят сквозь сугробы, чтобы не застревать при запрете повторной посадки.
Если безопасная фиксация невозможна или достигнут лимит плотности, частица освобождается и падает.
Ветер влияет на скорость/ускорение падающих снежинок и на сам сугроб: слабые порывы
не срывают его, длительные сильные преодолевают сцепление и сбивают частицы по ветру.
Учитываются подъёмная сила, турбулентность, размер частиц и независимое от FPS затухание.
Прокрутка (включая вложенные контейнеры) осыпает ряд сразу.
При изменении расположения частицы следуют за опорой.
Движение мыши также сбивает осевшие снежинки в пределах `mouseRadius`, включая быстрые
проходы курсора. Левая/правая кнопка сбивает их в существующем расширенном радиусе эффекта.
Неподвижный курсор не осыпает снег; `mouseRadius: 0` отключает сбивание указателем.
Удаление опоры или появление информации в полосе размещения возвращает частицы в падение
для безопасности; явные `clearAccumulation` и отключение накопления тоже осыпают ряд.
Во время прокрутки и 350 мс после неё накопление приостановлено.
GIF и предложения не накапливаются; внутренности iframe/shadow DOM не сканируются.

`durationMs` для GIF/ветра ограничено диапазоном 500–120000 мс; исключение — `wind`, который принимает `0` для
постоянного переопределения. Размер команды — не более 32 КиБ.

Возможные ошибки: `unknown_command`, `invalid_params`, `invalid_id`, `symbols_required`,
`valid_https_urls_required`, `invalid_coordinates`, `effect_limit_reached`, `live_config_required`,
`not_running`, `rate_limited`, `payload_too_large` и `page_api_disabled`.

## 1. Быстрые эффекты во всплывающем окне и синхронизация окон

- Кнопки **«Снежный взрыв» / «Сильный ветер» / «Убрать эффекты»** отправляют команды в текущую вкладку.
- **«Все вкладки и окна»**: запуск/остановка и команды API уходят во все открытые вкладки всех
  окон этого браузера, а не только в активную вкладку.
- Чтобы синхронизировать **два разных браузера** (например, Chrome и Firefox), включите подключение к relay
  в обоих (см. ниже) с одинаковым URL relay и токеном. Команда, отправленная из любого из них или по HTTP,
  доходит до всех.
- Синхронизация передаёт команды, а не одинаковые позиции снежинок или все визуальные настройки. Команды,
  полученные через relay, направляются во все вкладки, где можно выполнять скрипты, независимо от
  переключателя синхронизации во всплывающем окне.
- Быстрые эффекты сообщают о недоступности relay или отсутствии получателей; если отправка через relay
  не удалась после локальной доставки, всплывающее окно всё равно показывает, сколько вкладок получили команду.

## 2. Локальный relay (HTTP / WebSocket)

Relay — небольшой сервер на Node.js без зависимостей. Он слушает только loopback-интерфейс.

```bash
pnpm build          # также собирает dist/obs (или: pnpm build:obs)
pnpm relay          # выводит URL и сгенерированный токен
pnpm relay -- --port 8787 --token "<не менее 24 символов>"
# или: SNOW_RELAY_TOKEN=... pnpm relay
```

Параметры: `--port`, `--host` (только loopback), `--token`, `--token-file <path>`, `--allow-origin <origin>` (можно повторять),
`--allow-file-origin`, `--static-dir`, `--pid-file <path>`, `--parent-pid <pid>` (завершиться, когда завершится этот процесс),
`--quiet`, `--version`.

### Автономный relay (без Node.js / pnpm)

В релизах публикуются архивы `let-it-snow-relay-<windows|macos|linux>-<arch>.zip`: один исполняемый файл
(Node.js SEA со встроенным оверлеем OBS), скрипт OBS `let-it-snow-relay.lua` и README.
Локальная сборка — `pnpm build:relay` (требуется Node.js ≥ 25.5; SEA не поддерживает кросс-компиляцию, поэтому CI собирает
каждую ОС на собственном раннере).

- Двойной щелчок по исполняемому файлу: без `--token` он читает или создаёт постоянный токен в
  `%APPDATA%\LetItSnow\relay-token.txt` (Windows), `~/Library/Application Support/LetItSnow/relay-token.txt`
  (macOS) или `$XDG_CONFIG_HOME/let-it-snow/relay-token.txt` (Linux), права файла `0600`.
- OBS: *Инструменты → Скрипты → +* → `let-it-snow-relay.lua` (держите его рядом с исполняемым файлом). Скрипт запускает relay
  вместе с OBS (`--parent-pid`, токен передаётся через `SNOW_RELAY_TOKEN`, а не в командной строке), останавливает его при выходе,
  а кнопка *Add / update browser source* создаёт источник оверлея в текущей сцене.

Подключение расширения: **API → «Локальный relay (браузеры и OBS)»**. Включите *«Подключаться к relay»*, оставьте
`ws://127.0.0.1:8787/ws` и вставьте токен (или нажмите *«Новый токен»* и запустите relay с этим токеном).
Строка статуса показывает состояние подключения и число клиентов.
Также в ней отображаются ошибки отправки через relay или доставки во вкладки, пока подключение остаётся открытым.

### HTTP

```bash
curl -X POST http://127.0.0.1:8787/api/command \
  -H "Authorization: ******" \
  -H "Content-Type: application/json" \
  -d '{"command":"burst","params":{"count":500,"durationMs":8000}}'
# → 202 {"ok":true,"delivered":2,"id":null}
```

Ответы:
- `401`: неверный токен.
- `403`: origin не разрешён.
- `413`: размер запроса больше 32 КБ.
- `415`: не JSON.
- `429`: превышен лимит частоты (60 команд за 10 с).
- `400`: ошибка валидации.

`GET /health` возвращает `{"ok":true,"service":"let-it-snow-relay"}` без токена.
`delivered` — число подключённых клиентов relay, а не вкладок или подтверждённых визуальных эффектов.

### WebSocket (`/ws`)

1. В течение 5 с отправьте `{"type":"auth","token":"…","client":{"kind":"client","name":"my-bot"}}`.
   При неверном токене сокет закрывается с кодом `4401`.
2. Relay отвечает `{"type":"auth_ok","clientId":"…","peers":N}`, а затем присылает сообщения `{"type":"peers","peers":N}`.
3. Отправьте `{"type":"command","command":"wind","params":{"strength":3}}`. Relay перешлёт её всем
   остальным аутентифицированным клиентам в виде `{"type":"command",…,"from":"client"}`.
4. Отправьте `{"type":"ping"}`, чтобы получить в ответ `{"type":"pong"}`. Неактивные соединения закрываются через 90 с.

Лимиты: 32 клиента и 30 команд за 10 с на клиента.

## 3. API страницы (по явному разрешению, для каждого origin)

Веб-страница, которой вы доверяете (например, ваша собственная панель управления стримом), может управлять снегом
в своей вкладке через `window.postMessage`. Во всплывающем окне в разделе **«API для сайтов»** включите
**«Разрешить команды со страниц»** и перечислите точные разрешённые origin, по одному в строке
(например, `https://my-dashboard.example`). Значения `*` и `null` отклоняются.

```js
window.addEventListener('message', (event) => {
  if (event.source === window && event.data?.target === 'let-it-snow-api-response') {
    console.log(event.data); // { ok, error?, id, target }
  }
});

window.postMessage({
  target: 'let-it-snow-api',
  id: 'req-1',
  command: 'glyphs',
  params: { symbols: ['🎉', '✨'], glyphMode: 'emoji', count: 80 }
}, window.location.origin);
```

Команды страницы влияют только на текущую вкладку. Они никогда не рассылаются в другие вкладки или в relay.
Их лимит — 20 за 10 с. GIF по URL со страницы загружаются с правами самой страницы;
расширение не скачивает их через свой фоновый скрипт, поэтому CORS никогда не обходится.

## 4. Источник «Браузер» в OBS

1. Выполните `pnpm build` (или `pnpm build:obs`) и запустите `pnpm relay`.
2. Во всплывающем окне нажмите **«Ссылка для OBS»** или соберите URL вручную:
   `http://127.0.0.1:8787/obs/?snowmax=120&renderer=3d#token=<token>`
3. В OBS добавьте источник **«Браузер»** с этим URL и размером холста. Фон прозрачный,
   поэтому пользовательский CSS не нужен.

Параметры запроса:
- `snowmax`, `speed`, `minsize`, `maxsize`
- `colors` (через запятую, `#` в URL-кодировке), `symbols`, `glyphMode`
- `renderer` (`auto`/`3d`)
- `wind`, `windDirection`, `windStrength`
- `relay` (собственный loopback-URL ws), `name`
- `snow=0` (только эффекты, без основного снега), `status=0` (скрыть значок подключения)

Токен передаётся в **хеше** URL (`#token=`), который не отправляется в HTTP-запросе.
Relay выводит токен при запуске, а OBS хранит полный URL в настройках источника;
не раскрывайте ни то, ни другое. Оверлей ставится на паузу, когда OBS скрывает источник, и повторно
подключается к отключившемуся relay с нарастающей задержкой.

## Модель безопасности

- **Только по явному включению**: relay, API страницы и синхронизация окон по умолчанию выключены.
- **Только loopback**: relay привязывается к `127.0.0.1`/`::1`/`localhost` и отклоняет другие заголовки `Host`
  (защита от DNS rebinding, `421`). Расширение подключается только к loopback-адресам `ws://`/`wss://`.
- **Аутентификация**: общий токен (≥24 символов), сравниваемый за постоянное время. HTTP-запросы также должны
  отправлять `Content-Type: application/json`, что блокирует простые межсайтовые отправки форм.
- **Origin**: запросы из браузера принимаются только с origin расширений, собственного origin relay
  или из записей `--allow-origin`. Relay не отправляет CORS-заголовки.
- **Валидация**: строгая схема, ограничение чисел, очистка символов (без управляющих и bidi-символов),
  белый список цветов, фильтрация HTTPS-URL изображений, ограничения размера запроса и частоты на каждом звене.
- **Обмен сообщениями в расширении**: сообщения диспетчеризации, синхронизации и relay принимаются только от
  собственных страниц расширения. Контент-скрипты игнорируют сообщения `snowCommand` от других отправителей.
- **Защищённая загрузка GIF**: фоновые загрузки разрешают `http(s)`, отклоняют типы содержимого, отличные от
  изображений (если тип указан), и прекращают чтение после 15 МиБ. Если фоновая загрузка не удалась, возможен
  откат к прямой загрузке изображения браузером, на которую это ограничение размера не распространяется.
  Проверки имени хоста в URL не проверяют результаты DNS и адреса перенаправлений; используйте только
  доверенные источники изображений и передавайте токен только доверенным управляющим программам.
- **Страница OBS**: отдаётся со строгой CSP; раздача статических файлов защищена от выхода за пределы каталога (path traversal).
- Расширение хранит свой токен в `chrome.storage.local`, а не в синхронизируемом хранилище. Relay
  выводит его при запуске, и URL источника OBS тоже его содержит. Изображения, указанные пользователем,
  запрашиваются с соответствующих серверов.
